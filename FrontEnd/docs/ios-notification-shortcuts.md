# iOS 27 알림 → MemoA 단축어 연동

이 기능은 iOS 27의 알림 자동화와 MemoA의 **알림을 MemoA에 임시저장** 동작을 연결합니다.
새 IPA를 설치해야 동작이 나타납니다. Expo Go와 이전 IPA에는 이 네이티브 동작이 없습니다.

## 처음 한 번 설정

1. 새 IPA를 Sideloadly로 설치하고 MemoA를 한 번 실행합니다.
2. MemoA **설정 → iPhone 알림 자동화**에서 안내를 확인합니다.
3. iPhone의 단축어 앱에서 새 단축어를 만들고 **편집 → 자동화 → 알림**을 선택합니다.
4. 카카오톡, 문자, Instagram 등 일정 메시지를 받을 앱만 선택합니다.
   MemoA 자체는 선택하지 않습니다. 날씨·뉴스 앱도 필요한 경우에만 선택합니다.
5. 동작을 추가하고 **MemoA → 알림을 MemoA에 임시저장**을 선택합니다.
6. 각 입력칸에 해당 알림의 변수를 연결합니다. 고정된 예시 문장을 입력하지 않습니다.

| MemoA 입력 | 단축어의 수신 알림 변수 |
| --- | --- |
| 알림 내용 | 본문 / Message / Body |
| 앱 이름 | App |
| 알림 제목 | Title |

7. 자동화를 활성화하고 실행 전 확인을 끕니다. 잠금 상태에서 실행하려면 단축어의
   **정보 → 개인정보 보호 → 잠금 중 실행 허용**도 확인합니다.
8. 임시저장 시 소리를 받으려면 MemoA **설정 → 감지 알림**에서 알림 권한을 허용합니다.

메뉴 이름은 iOS 언어와 버전에 따라 다를 수 있습니다.
Apple의 [새 단축어 기능 안내](https://support.apple.com/en-mide/149045)와
[자동화 설정 안내](https://support.apple.com/en-om/guide/shortcuts/apdfbdbd7123/10.0/ios/27)를 참고합니다.

## 동작

- 단축어에서 선택한 앱의 **설정 이후 새 알림**만 전달됩니다. 알림 기록 전체를 읽지 않습니다.
- 날짜·시간·회의·제출 등 일정 표현이 있는 본문만 후보로 저장합니다.
  이 사전 필터는 모든 문장을 이해하는 AI가 아니므로 표현에 따라 놓칠 수 있습니다.
- 본문을 기기에 먼저 저장하고 기존 Spring Boot `/analysis` API로 분석합니다.
  앱 이름과 발신자 제목을 AI 메시지에 덧붙이지 않습니다. 전달 경로는 기존 `SHARE` 유형을 사용합니다.
- 서버 연결이 끊기거나 실행이 중단되어도 후보는 남습니다. MemoA 홈을 열면 다시 분석합니다.
- 홈에서 후보를 확인하고 수정한 뒤 저장합니다. 저장하거나 삭제한 후보는 늦은 AI 응답으로 복원하지 않습니다.
- 기기에는 최대 50개의 후보를 보관합니다. 같은 내용의 반복 실행은 90초 동안 중복 저장하지 않습니다.
- Groq API 키는 백엔드에만 있으며 IPA나 단축어에 넣지 않습니다.

## 테스트 순서

1. iPhone과 PC를 같은 Wi-Fi에 연결하고 PC 백엔드를 실행합니다.
2. 단축어를 수동 실행하면서 `내일 오후 2시 회의실에서 회의, 노트북 지참`을 입력합니다.
3. MemoA 홈에 후보가 표시되고, 확인 화면에 제목·날짜·시간·장소·준비 사항이 나뉘는지 확인합니다.
4. 선택한 앱에서 실제 메시지 알림을 받아 자동 실행되는지 확인합니다.
5. 화면을 잠근 상태, 서버를 끈 상태에서도 각각 시험합니다.

알림에 본문이 숨겨져 있거나 단축어가 빈 내용을 전달하면 분석할 수 없습니다.
실제 앱별로 **미리보기 / Quick Look** 동작을 임시로 넣어 본문 변수가 전달되는지 먼저 확인합니다.
서버 주소가 PC의 사설 IP인 현재 테스트 빌드는 같은 네트워크에서만 AI 분석이 가능합니다.

Windows에서는 iOS의 실제 알림 전달과 잠금 상태 실행을 재현할 수 없습니다.
소스 검사·자동 테스트·실기기용 IPA 빌드 성공과 실제 iPhone 동작 확인은 구분합니다.
